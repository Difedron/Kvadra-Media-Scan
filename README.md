
# KvadraMediaScan

`KvadraMediaScan` — консольное приложение на C++ под Linux, которое сканирует заданный каталог, находит в нём мультимедийные файлы и формирует JSON со списками найденных аудио, видео и изображений.

Проект выполнен для тестового задания в команду **kvadraOS Desktop (Команда 4)**.


---
## !Примечание о первом запуске!

В ходе тестирования программы на других устройствах выяснилось, что при сканировании больших директорий первый обход может занять некоторое время.  
Это связано с тем, что программа рекурсивно проходит по выбранному каталогу и всем его вложенным папкам, проверяет расширения файлов и формирует JSON в памяти.

HTTP-сервер запускается сразу, однако актуальный JSON становится доступен после первого успешного сканирования каталога.

В консоли это отображается сообщением вида:

```text
Media JSON was rebuilt
Audio files: 4487
Video files: 5366
Image files: 65637
----------------------------------------
```
После этого сообщения можно переходить по ссылке.

## Что делает это приложение?

- обходит указанный каталог через равные интервалы времени, которые задает пользователь;
- ищет мультимедийные файлы;
- распределяет найденные файлы по категориям:
  - `audio`;
  - `video`;
  - `images`;
- формирует результат в формате JSON;
- эта версия программы не создаёт JSON-файл в файловой системе, а сразу отдаёт его через HTTP по адресу:

```text
http://localhost:1234/media_files
````

В проекте реализованы дополнительные задачи:

* путь до сканируемого каталога можно задать при запуске;
* периодичность обновления можно задать при запуске;
* результат доступен через HTTP GET-запрос вместо создания файла `.media_files`.

## Формат результата

Пример JSON-ответа:

```json
{
  "audio": ["111.mp3", "222.wav"],
  "video": ["333.mpg"],
  "images": ["444.jpeg", "555.png"]
}
```

---

## Поддерживаемые расширения

### Audio

```text
.mp3
.wav
.flac
.aac
.ogg
```

### Video

```text
.mp4
.mpg
.mpeg
.avi
.mkv
.mov
```

### Images

```text
.jpg
.jpeg
.png
.bmp
.gif
.webp
```

Важный момент: расширения обрабатываются без учёта регистра, поэтому файлы вида `song.MP3`, `photo.JPG` и `video.Mp4` также будут распознаны корректно.

## Запуск программы

Общий формат запуска:

```bash
./kvadra_media_scan [path] [interval_seconds]
```

Также поддерживается формат:

```bash
./kvadra_media_scan [interval_seconds]
```

Тогда путь не задаётся, и программа сканирует домашний каталог.

Ниже показан примеры запуска:

### Запуск без аргументов

```bash
./kvadra_media_scan
```

В этом случае программа:

```text
сканирует домашний каталог пользователя
обновляет JSON каждые 120 секунд
запускает HTTP-сервер на localhost:1234
```

### Запуск только с интервалом

```bash
./kvadra_media_scan 10
```

В этом случае программа:

```text
сканирует домашний каталог пользователя
обновляет JSON каждые 10 секунд
запускает HTTP-сервер на localhost:1234
```

### Запуск с указанием каталога

```bash
./kvadra_media_scan /home/user/test_media
```

В этом случае программа:

```text
сканирует каталог /home/user/test_media
использует интервал обновления по умолчанию — 120 секунд
запускает HTTP-сервер на localhost:1234
```

### Запуск с указанием каталога и интервала

```bash
./kvadra_media_scan /home/user/test_media 10
```

В этом случае программа:

```text
сканирует каталог /home/user/test_media
обновляет JSON каждые 10 секунд
запускает HTTP-сервер на localhost:1234
```

## Проверка HTTP-запроса

После запуска программы JSON доступен по адресу:

```text
http://localhost:1234/media_files
```

Проверить работу можно через браузер или через `curl`.

Например, в другом терминале:

```bash
curl http://localhost:1234/media_files
```

Пример ответа:

```json
{
  "audio": ["song.mp3", "track.wav"],
  "video": ["movie.mp4"],
  "images": ["photo.png", "image.jpeg"]
}
```

Если обратиться к другому адресу, сервер просто вернёт Not Found.

## Особенности реализации

Программа не создаёт файл `.media_files` на файловой системе. Вместо этого JSON хранится в памяти приложения и отдаётся через HTTP по GET-запросу.

Обновление JSON выполняется в отдельном потоке. Этот поток периодически пересканирует выбранный каталог и обновляет JSON-кэш.

HTTP-сервер работает в основном потоке и отдаёт последний актуальный JSON по адресу:

```text
GET /media_files
```

Для защиты доступа к JSON-кэшу используется `std::mutex`, так как один поток обновляет JSON, а HTTP-сервер может читать его при обработке запроса.

Недоступные директории при обходе пропускаются, чтобы программа не завершалась с ошибкой при отсутствии прав доступа к отдельным папкам.
